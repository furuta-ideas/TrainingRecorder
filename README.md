# R-Bodyトレーニング記録

手描きUIに合わせたレスポンシブWebアプリ。教材は指定されたNotionの2026年10月9日復習ガイドから取り込んだ15種目、写真15点、動画11点です。既存のツアーFAQとは別のフォルダーに実装しています。

## 起動

このフォルダーで `node preview.mjs` を実行し、http://127.0.0.1:8781 を開きます。単純なファイルダブルクリックではなくHTTP/HTTPS経由で使用してください。iPhone・iPadはホストされたHTTPSのURLをSafariで開きます。

## 操作

- 右下に前・次ボタン、メニュー選択、開始／終了を集約しています。「開始」はグレー、実施中は緑色の「終了」と表示します。時計はその下に現在時刻を表示する専用エリアです。
- 「終了」で時間計測とマイクを停止し、メモ・合算時間をログに自動保存します。同じメニューで再度「開始」した場合は実施時間を加算し、同じログを更新します。停止中の時間は含みません。
- 前・次ボタン、メニュー選択でも自動保存します。移動先の実施時間はゼロ、マイクはOFFです。戻ってきた場合も新しい実施記録になります。終了直後に移動しても同じログを重複作成しません。
- マイクアイコンは音声入力のON／OFF、鉛筆アイコンは手入力／完了です。時間計測とは独立しています。初回はマイクの許可が必要です。拒否・音声エラー時もトレーニングの計測は継続し、手入力を利用できます。音声ファイルそのものは保存しません。停止後に遅れて届いた音声イベントは破棄します。
- 動画がある種目は動画だけを最大表示し、写真は表示しません。動画のない種目は白い背景で写真を大きく表示し、複数枚なら縦に並べます。写真には黒い背景や枠を付けません。
- トレーニング内容は最大3行。1行目は回数と指導された時間（未指定なら「時間指定なし」）。2行目は教材のコツ、3行目は過去の気づきを短く抽出した内容です。外部AIへの送信は行わず、端末内の文抽出・重複削除・文字数制限で更新します。
- 動画は音声なし・インライン・自動ループ再生。Safariの省電力設定などで自動再生が止まる場合は再生ボタンを押してください。
- 記録と入力中のメモ・計測状態はlocalStorage、過去に追加した教材はIndexedDBから読み込みます。画面を離れた場合は音声入力と計測を停止し、自動保存します。再読み込み後は停止状態から開始ボタンで再開します。
- 保存・書き出し・メニュー追加・日付表示の各ボタン／表示は画面から削除しました。過去の記録・教材は引き続き保持します。端末間の自動同期はありません。ブラウザのサイトデータ削除で端末内データは消えます。

## メニューの追加

画面のメニュー追加ボタンはありません。今後の教材追加は以下の共通メニューデータへ行います。

全端末に共通のメニューを増やす場合は、`dist/menus.json` の `menus` にレコードを追加し、`dist/media/` に教材を追加して再公開してください。既存の `id` は変更しないでください。ログとの対応を維持します。

```json
{
  "id": "変更しない一意なID",
  "name": "トレーニング名",
  "prescription": "2セット × 10回",
  "durationNote": "時間指定なし",
  "tips": "教材から確認したフォームのコツ",
  "images": [{"src":"media/example.png","notionRef":"Notionの安定ファイル参照"}],
  "video": {"src":"media/example.mp4","notionRef":"Notionの安定ファイル参照"},
  "needsConfirmation": false
}
```

動画なしは `video: null`。Notionの期限付き署名URLは保存せず、安定参照と取り込んだ教材ファイルを保持します。Notionのログイン情報・支払い情報などトレーニングに不要な内容は含めていません。Notionとの自動同期やNotionへの書き戻しはありません。

## 検証

`node --test tests/*.test.js`：中断・再開、再読み込み、メモ要約、教材の実在と件数を検証します。

## トレーニング終了メール

右下「トレーニング終了」で計測とマイクを停止し、進行中の記録を保存したうえで、日本時間の当日のログを送信します。宛先は furuta.ideas@gmail.com、件名は「yyyymmdd 本日のトレーニング内容」。本文には各種目の日時・名称・メモ・実施時間と合計を記載します。

送信先はサーバー側でも固定します。送信中の連打を禁止し、同じ内容は端末の送信済み情報とResendのIdempotency-Keyで重複を防ぎます。結果不明時は成功表示せず、ログを端末に保持します。Resendで受け付けられたことと、宛先メールボックスへの到着は別です。

### Resend設定（未設定では送信できません）

1. Resendに furuta.ideas@gmail.com で登録し、メール送信権限のAPIキーを発行します。既定の onboarding@resend.dev はResendアカウント本人宛てのテスト送信専用です。別のアカウントを利用する場合はドメインを認証し、そのドメインの送信元アドレスを指定してください。
2. ローカルで `./scripts/setup-mail.ps1` を実行し、APIキーを非表示入力します。生成する `.env.local` はGit管理対象外です。キーをチャットやGitHubへ貼り付けないでください。
3. Sitesのサーバー環境変数へ `RESEND_API_KEY` を秘密値として登録します。任意で `R_BODY_MAIL_FROM` に認証済み送信元を設定します。設定後は保存済みの版を再デプロイして反映します。

### サーバー構成

静的ページを同じURLのWorkerへ移行しています。ブラウザは同一オリジンへPOSTし、サーバーでログイン・Origin・データ形式を検証してResend APIを呼びます。送信サービスのキーをブラウザへ返しません。

`node scripts/build-worker.mjs` でHTML・JS・アイコンを埋め込んだ `dist/server/index.js` を生成し、`node scripts/validate-worker.mjs` で確認します。教材メディアはPublicリポジトリのコミット `6bc773f6ee3188bcf5c3ce7ba1963c9d8dbbc478` から固定パスだけを代理配信します。新しい教材ファイルを追加する際は、GitHubへ保存後にビルドスクリプト内の教材コミット参照も更新してください。

ローカルプレビューのメールAPIは未設定エラーを返します。実メールを送るテストは行いません。送信テストは `tests/mail.test.js` の疑似Resend応答で行います。

## iPhone・iPadのホーム画面アイコン

Safariでアプリ画面までログインし、共有メニューから「ホーム画面に追加」します。認証画面を追加しないでください。既存のホーム画面ショートカットに古いアイコンが残る場合は、ショートカットのみを削除して追加し直します。Safariのサイトデータは記録を含むため削除しないでください。

本人限定のSitesでは、アイコン画像にも認証が適用されます。iOSの画像取得でログイン情報が使われない場合に備え、apple-touch-iconとmanifest内のアイコンには、既にPublicのTrainingRecorderリポジトリ上にあるPNGを参照します。参照先はコミット固定です。アプリの公開範囲は変更しません。ルートの標準名apple-touch-icon.pngも配置します。
